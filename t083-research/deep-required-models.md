# Research: Flux T083 required AI matte/depth models

## Summary
CUDA-first implementation is feasible, but legal bundling is mixed. Best default/test order is: BiRefNet for fast still/base mattes, SAM 3.1 for viewer-selected prompt masks/tracks where HF gated access is accepted, ViTMatte for trimap/refinement, MatAnyone2 only as optional/non-commercial research unless licensed, and DepthCrafter only optional/non-commercial for video-stable depth.

## Findings
1. **SAM 3 / SAM 3.1 is real and current; “SAM 3+” does not appear to be an official separate release.** Official current line is `facebookresearch/sam3`; SAM 3.1 released 2026-03-27 as a drop-in update with Object Multiplex/shared-memory multi-object video tracking, new checkpoints, and claimed ~7x speedup at 128 objects on H100 versus SAM 3 Nov 2025. [Release notes](https://github.com/facebookresearch/sam3/blob/main/RELEASE_SAM3p1.md) [Repo](https://github.com/facebookresearch/sam3) [Meta blog](https://ai.meta.com/blog/segment-anything-model-3/?_fb_noscript=1)
2. **SAM 3.1 IO contract fits Flux viewer selection.** It supports image/video promptable concept segmentation: text prompts, visual prompts/points/boxes/masks/image exemplars; video path predicts masks and stable object IDs over frames. Use it as the base matte/track generator from viewer points/boxes/text, output per-frame alpha/mask images back into Flux mask nodes. [HF SAM3 docs](https://huggingface.co/docs/transformers/model_doc/sam3) [HF SAM3 Video docs](https://huggingface.co/docs/transformers/main/model_doc/sam3_video)
3. **SAM 3.1 license permits redistribution under Meta SAM License, but not OSI-open and has use restrictions.** License grants use/reproduction/distribution/derivatives but requires redistribution under same agreement, trade-control compliance, no reverse engineering, and prohibited military/ITAR/end-use clauses. Commercial use is not plainly banned, but GPL2 compatibility and bundled redistribution need legal review. [License](https://github.com/facebookresearch/sam3/blob/main/LICENSE)
4. **SAM 3 / 3.1 weights are gated on Hugging Face.** Installation must support requesting HF access and storing a token securely, never plaintext. Recommended: Qt credential flow -> libsecret/KWallet/Secret Service; fallback prompt-per-session; pass token to `huggingface_hub` env/session only. Do not bundle gated weights by default unless Meta/HF terms and token-gated redistribution are cleared. [HF model](https://huggingface.co/facebook/sam3.1/blob/main/README.md) [Microsoft catalog notes gated access](https://ai.azure.com/catalog/models/facebook-sam3)
5. **MatAnyone2 is the best-looking target-assigned human video matting refiner, but license blocks commercial/default bundling without permission.** Repo: `pq-yang/MatAnyone2`; CVPR 2026 Highlight; input is video folder/mp4/mov/avi plus first-frame segmentation mask, output foreground video and alpha video/per-frame images. Python API: `MatAnyone2.from_pretrained("PeiqingYang/MatAnyone2")`, `InferenceCore(..., device="cuda:0")`, `process_video(input_path, mask_path, output_path)`. It auto-downloads `matanyone2.pth` or downloads from GitHub release. License is NTU S-Lab License 1.0, non-commercial only; commercial use requires contacting authors. [README](https://github.com/pq-yang/MatAnyone2/blob/main/README.md) [License](https://github.com/pq-yang/MatAnyone2/blob/main/LICENSE.txt)
6. **MatAnyone original is similar but older.** Repo: `pq-yang/MatAnyone`; CVPR 2025 stable video matting with consistent memory propagation; same practical IO class: input video + first-frame target mask, output alpha/foreground. Use only as fallback if MatAnyone2 fails or for comparison. License is also restrictive/non-commercial S-Lab-style. [README](https://github.com/pq-yang/MatAnyone/blob/main/README.md) [HF](https://huggingface.co/PeiqingYang/MatAnyone)
7. **MatAnything family is not the same as MatAnyone2 and is less attractive for Flux’s required video-stable human matte workflow.** It is useful as an interactive/image matting family conceptually, but Nick’s requested pipeline is better served by SAM3.1 viewer selection -> MatAnyone2 video matte refinement or ViTMatte edge refinement. Keep MatAnything-style tools as optional later only after license/perf review.
8. **BiRefNet is the safest default bundled base-matte/background-removal model.** Repo: `ZhengPeng7/BiRefNet`; MIT license; Hugging Face models include `ZhengPeng7/BiRefNet`, `BiRefNet_HR`, `BiRefNet_lite`; trained variants include 2048x2048 HR. IO is RGB image -> single-channel dichotomous segmentation probability/mask, good for high-res foreground/background extraction. Weights are MIT-tagged on HF for at least HR/lite pages. [Repo](https://github.com/ZhengPeng7/BiRefNet) [HF HR](https://huggingface.co/ZhengPeng7/BiRefNet_HR/blob/main/README.md) [License](https://github.com/ZhengPeng7/BiRefNet/blob/main/LICENSE)
9. **BiFormer is an architecture component, not the implementation target here.** For Flux, treat “BiFormer/BiRefNet-style” as a model class requirement: high-resolution dichotomous segmentation/background removal. Implement BiRefNet first because it has active repo, MIT code, HF/ONNX availability, and explicit HR variants. [BiRefNet repo](https://github.com/ZhengPeng7/BiRefNet)
10. **ViTMatte is a legal, good edge-refinement candidate but requires trimaps.** Repo: `hustvl/ViTMatte`; MIT license; in Hugging Face Transformers. IO contract is image + trimap -> alpha matte. Flux can generate trimap by erode/dilate of base mask from SAM/BiRefNet, then feed ViTMatte for edge quality on current frame or selected frames. [Repo](https://github.com/hustvl/ViTMatte/blob/main/README.md) [HF docs](https://huggingface.co/docs/transformers/model_doc/vitmatte) [License](https://github.com/hustvl/ViTMatte/blob/main/LICENSE)
11. **RVM is very fast and mature, but GPL3 conflicts with Flux GPL2-only if linked/bundled as integrated code.** Repo: `PeterL1n/RobustVideoMatting`; provides PyTorch/TorchScript/ONNX/CoreML/TensorFlow exports; claimed real-time 4K 70+ FPS and HD 100+ FPS, with recurrent state IO for temporally guided human matting. License is GPL-3.0. For Flux GPL2, avoid linked/bundled integration unless legal approves GPL3 aggregation/subprocess design or Flux relicensing is possible. [Project](https://peterl1n.github.io/RobustVideoMatting/) [README](https://github.com/PeterL1n/RobustVideoMatting/blob/master/README.md) [License](https://github.com/PeterL1n/RobustVideoMatting/blob/master/LICENSE)
12. **XMem2/XMem++ is useful for semi-supervised video object segmentation propagation, not alpha-quality matting.** Repo: `max810/XMem2`; improves XMem with permanent memory; input is frames/video plus initial masks/annotations, output propagated segmentation masks. License GPL-3.0, so same GPL2 integration problem as RVM. Use only as optional external helper if SAM3.1 tracking is unavailable/too heavy. [README](https://github.com/max810/XMem2/blob/main/README.md) [License](https://github.com/max810/XMem2/blob/main/LICENSE)
13. **DepthCrafter is the best match for Nick’s video-stable depth warning, but cannot be commercial/default bundled without permission.** Repo: `Tencent/DepthCrafter`; CVPR 2025 Highlight; generates temporally consistent long depth sequences from video without camera poses/flow. IO: video path -> depth/disparity outputs, EXR supported. Perf/VRAM from README: ~26GB GPU for 1024x576, ~2.1 fps on A100; low-res 512x256 needs ~9GB, ~8.6 fps on A100; v1.0.1 table reports 465.84 ms/frame @1024x576. License explicitly limits code/weights to academic, research, education and forbids commercial/production use. [README](https://github.com/Tencent/DepthCrafter/blob/main/README.md) [License](https://github.com/Tencent/DepthCrafter/blob/main/LICENSE)

## Implementation contracts for Flux
- **Model host:** use a separate CUDA Python worker process, not in-process C++ linking. Communicate by local IPC/JSON + frame files or shared temp EXR/PNG sequences. This isolates PyTorch/CUDA deps, avoids Natron UI crashes, and reduces GPL/license coupling risk.
- **Default install:** install Python worker and permissive models after test: BiRefNet + ViTMatte first. Do not auto-install gated/restrictive weights until user accepts terms and/or license is cleared.
- **Secure HF token:** if SAM3.1 or HF weights require auth, request token in AI preferences, store via Secret Service/KWallet/libsecret; never write plaintext config. Cache weights under `$XDG_CACHE_HOME/flux-ai/models` with manifest/license metadata.
- **Viewer selection:** AI panel exposes model selector and prompt mode: point/box/text/current alpha. It sends current viewer frame and user prompts to worker. Nodegraph node receives result as generated mask sequence/alpha clip and can be used in masks/effects like any other Flux-managed node.
- **Base matte flow:** `Viewer selection -> SAM3.1 or BiRefNet base mask -> trimap generation -> ViTMatte per-frame edge refine` for stills/short clips. For human video, `first-frame SAM3.1/BiRefNet mask -> MatAnyone2 alpha sequence` if legal/optional.
- **Depth flow:** `video clip -> DepthCrafter worker -> EXR depth sequence -> Flux Depth node/read sequence`, optional only unless commercial permission obtained.

## Recommended tested implementation order
1. **BiRefNet still/base matte node** — permissive MIT, easiest default bundle, validates CUDA worker, alpha output, nodegraph usability, AI panel model selection.
2. **ViTMatte refinement node** — MIT, builds the required “base matte refined for edge quality” path using generated trimaps.
3. **SAM 3.1 gated optional integration** — viewer point/box/text selection and video tracking. Implement secure HF token and access-request UX here.
4. **MatAnyone2 optional research plugin** — only after Nick/legal decide non-commercial restriction is acceptable for internal testing or permission is obtained. It is the strongest candidate for human video matte refinement.
5. **DepthCrafter optional depth tool** — prove EXR depth-sequence workflow and VRAM controls; do not bundle commercially without Tencent permission.
6. **RVM/XMem2 external helpers only** — useful fallback/perf baselines, but GPL3 makes default integrated bundling risky for GPL2-only Flux.

## Gaps
- Exact RTX 4090 VRAM/perf must be benchmarked locally; most published figures are A100/H100 or generic.
- SAM 3.1 GPL2 compatibility and commercial redistribution need legal review despite no plain commercial ban.
- MatAnyone2 and DepthCrafter commercial permissions are required before default commercial bundling.
- Need local tests for ONNX/TensorRT export viability for BiRefNet/ViTMatte; PyTorch-first is the safe initial path.
